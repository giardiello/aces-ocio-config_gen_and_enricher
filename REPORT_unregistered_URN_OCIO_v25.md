# ~~Unregistered~~ ACEStransformID in OCIO v2.5 Configs — RESOLVED

## Resolution

**This issue is resolved.** The transform `CSC.Arri.ACES_to_LogC3.a2.v1` **does** exist as a published CTL in the ACES ecosystem. The CTL source is located at:

- **Repository:** [`aces-aswf/aces-input-and-colorspaces`](https://github.com/aces-aswf/aces-input-and-colorspaces)
- **File:** [`arri/CSC.Arri.ACES_to_LogCv3.ctl`](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/2383d3759514dc7f4c6c3a573b089f417ad3a9f1/arri/CSC.Arri.ACES_to_LogCv3.ctl)
- **URN:** `urn:ampas:aces:transformId:v2.0:CSC.Arri.ACES_to_LogC3.a2.v1`

The original report incorrectly concluded the URN was unregistered because it only checked `ampas/aces-dev`. The ACES 2.0 input/camera transforms are maintained in a separate repository (`aces-aswf/aces-input-and-colorspaces`), which is where this inverse CSC lives.

The bundled `transforms.json` in `OpenColorIO-Config-ACES` is **correct**, and the generated OCIO v2.5 configs contain valid URNs.

## Original Report (kept for reference)

### Summary

The official OCIO v2.5 configs generated by `OpenColorIO-Config-ACES` v4.0.0 contain one ACEStransformID URN that was initially believed to not exist in the ACES Transform Registry (`transforms.json` published at https://github.com/ampas/aces-dev):

```
urn:ampas:aces:transformId:v2.0:CSC.Arri.ACES_to_LogC3.a2.v1
```

This URN is written into the `interchange.amf_transform_ids` attribute of the **ARRI LogC3 (EI800)** color space in every Studio-tier config (both default and all-views variants). CG-tier configs are not affected because they do not carry `amf_transform_ids` for input color spaces.

### Affected Configs

All Studio configs generated by `OpenColorIO-Config-ACES` v4.0.0 for OCIO v2.5, including the upstream reference and studio configs shipped with the project:

| Config | Contains URN |
|--------|----------|
| `reference-config-v4.0.0_aces-v2.0_ocio-v2.5.ocio` | Yes |
| `studio-config-v4.0.0_aces-v2.0_ocio-v2.5.ocio` | Yes |
| `studio-config-all-views-v4.0.0_aces-v2.0_ocio-v2.5.ocio` | Yes |
| `cg-config-v4.0.0_aces-v2.0_ocio-v2.5.ocio` | No |

### What the Config Contains

The `ARRI LogC3 (EI800)` color space in the affected configs has:

```yaml
name: ARRI LogC3 (EI800)
interchange:
  amf_transform_ids: |
    urn:ampas:aces:transformId:v2.0:CSC.Arri.ACES_to_LogC3.a2.v1
    urn:ampas:aces:transformId:v2.0:CSC.Arri.LogC3_to_ACES.a2.v1
```

Both URNs are valid:

- `CSC.Arri.LogC3_to_ACES.a2.v1` — forward/input direction, in `ampas/aces-dev`.
- `CSC.Arri.ACES_to_LogC3.a2.v1` — inverse/output direction, in [`aces-aswf/aces-input-and-colorspaces`](https://github.com/aces-aswf/aces-input-and-colorspaces/blob/2383d3759514dc7f4c6c3a573b089f417ad3a9f1/arri/CSC.Arri.ACES_to_LogCv3.ctl).

### Original Root Cause Analysis (incorrect conclusion)

The original report stated the URN was missing from the ACES Transform Registry. This was because the analysis only checked `ampas/aces-dev` and not the `aces-aswf/aces-input-and-colorspaces` repository where ACES 2.0 camera/input CSC transforms are published.

### Note on ACES 2.0 Transform Repositories

ACES 2.0 transforms are split across multiple repositories:

| Repository | Content |
|-----------|---------|
| [`ampas/aces-dev`](https://github.com/ampas/aces-dev) | Core ACES transforms (RRT, ODTs, etc.) and the `transforms.json` registry |
| [`aces-aswf/aces-input-and-colorspaces`](https://github.com/aces-aswf/aces-input-and-colorspaces) | Camera/input CSC transforms (ARRI, Canon, Sony, RED, etc.) |

When validating URNs, both repositories must be consulted.
